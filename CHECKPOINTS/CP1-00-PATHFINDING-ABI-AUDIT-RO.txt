RUTA REALA DIN JOC
==================

1. PathfindNative.init() incarca System.loadLibrary("PZPathFind64").
2. DebugOptions.pathfindUseNativeCode controleaza selectia dintre PathfindNative si
   PolygonalMap2, fallback-ul Java original al jocului.
3. PathfindNative.useNativeCode este implicit true in clasa jocului.
4. PathfindNative.checkUseNativeCode() opreste ruta curenta, initializeaza ruta selectata si
   reincarca chunk-urile si vehiculele active.
5. PathfindNativeThread proceseaza task-urile de chunk/square/vehicle si cererile de pathfinding.
6. Ruta exercitata poate fi demonstrata pe iesirea normala din metoda Java wrapper
   PathfindNative.findPath(PathFindRequest, ByteBuffer, boolean), care apeleaza JNI findPath.

STAREA ZOMDROID INAINTE DE CP1
==============================

PathfindingWorkaround scrie neconditionat Pathfind.UseNativeCode=false pentru Build 42 cu
projectzomboid.jar. Din acest motiv libraria ARM64 poate fi prezenta si valida, dar ruta nativa
ramane dezactivata la fiecare lansare.

Agentul zomdroid-agent este deja incarcat de presetul Build 42, inclusiv cand mecanismele CP4 sunt
OFF. Poate fi folosit pentru dovada EXERCISED si pentru detectarea fail-open fara un agent nou.

DECIZIE DE IMPLEMENTARE
=======================

Nu se rescrie algoritmul Pathfinding in C++. Se integreaza libraria oficiala TIS identica pentru
42.20 si 42.20.3.

Gate-uri inainte de activare:

- familie Build 42;
- projectzomboid.jar prezent;
- hash exact pentru clasele PathfindNative, PathfindNativeRenderer si PathfindNativeThread;
- payload ELF64 AArch64 cu dimensiunea si SHA256 auditate;
- toate cele 13 exporturi JNI prezente;
- copiere atomica si verificare SHA256 dupa copiere.

Fallback:

- toggle OFF -> Pathfind.UseNativeCode=false;
- orice gate/copie esuata -> Pathfind.UseNativeCode=false si ruta Java originala;
- exceptie runtime din wrapperul findPath sau thread loop -> se cere false in DebugOptions,
  se inregistreaza PATHFINDING_NATIVE_FALLBACK si urmatorul checkUseNativeCode trece pe Java;
- eroarea unui request este suprimata numai dupa cererea fallback-ului, cu rezultat de path gol,
  pentru a evita crash-ul jocului.
